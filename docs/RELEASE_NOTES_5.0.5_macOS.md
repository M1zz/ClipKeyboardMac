ClipKeyboard v5.0.5

5.0.4 를 건너뛰고 5.0.5 로 갑니다. 아이폰 앱과 같은 번호를 쓰기 위해서입니다.
5.0.4 는 아이폰만 나간 판이라 맥에는 없습니다.
(빌드 번호는 전역 단조 증가라 18 입니다. 17 은 이미 올라가 있어서 건너뜁니다)

중국어를 넣습니다. 간체와 번체 두 벌입니다. 아이폰 앱 5.0.5 와 같은 말로 섭니다.

한국어

중국어를 쓰는 분이 이 앱을 중국어로 만납니다.

- **중국어 간체·번체를 넣었습니다**, 메뉴바, 빠른 붙여넣기 패널, 환경설정까지 모든 화면이 중국어로 섭니다. 앱 이름도 같이 바뀝니다. 번체는 글자만 바꾼 것이 아니라 대만에서 쓰는 말로 적었고, 시스템 설정 경로에 적힌 글자도 실제 화면과 맞췄습니다. 글자만 바꾸면 대만에서 읽는 분에게는 남의 나라 말이 그대로 남습니다
- **처음 켤 때 드리는 예시 단축어가 기기 언어를 따라갑니다**, 예전에는 기기가 중국어여도 영어 예시를 받았습니다. 한국어가 아니면 전부 영어였기 때문입니다
- **자동으로 채워지는 값의 이름이 한국어로만 보이던 것을 고쳤습니다**, 템플릿을 쓸 때 아래에 뜨는 날짜·시간·타임존·통화·인사·도시 여섯 개입니다. 번역이 어색했던 게 아니라 이 이름들이 번역 목록에 아예 없었습니다. 그래서 영어로 쓰시는 분도 한국어를 보고 계셨습니다. 이제 네 언어가 다 맞습니다
- 번역이 비어 있던 문구 몇 개도 함께 채웠습니다

English

People who read Chinese now meet this app in Chinese.

- **Simplified and Traditional Chinese are in**, the menu bar, the quick paste panel and Preferences all stand in Chinese, and the app name changes with them. Traditional is not just the characters swapped: it says the words Taiwan actually uses, and the System Settings paths match what is really on screen. Swapping only the characters leaves a mainland vocabulary sitting there for anyone reading in Taipei
- **The starter snippets now follow your device language**, before, a Chinese Mac still got the English samples, because anything that was not Korean fell through to English
- **Fixed the auto-filled value names showing only in Korean**, the six chips under the template editor: date, time, time zone, currency, greeting and city. They were not badly translated, they were never in the translation table at all, so English users were reading Korean too. All four languages are correct now
- Filled in a few strings that had been left untranslated

简体中文

中文来了。

有一位朋友问，能不能加上中文的支持。加上了，简体和繁体两套。菜单栏、快速粘贴面板、设置，每一个画面都用中文站着，App 的名字也跟着一起变。

繁体不是只把字换掉。用的是台湾那边在用的说法，引号也照那边的写法，系统设置的路径写得和实际画面对得上。只换字的话，台北的读者眼前留下的还是别人家的说法。

第一次打开时给你的示例短语，现在跟着设备语言走。以前设备是中文的话，拿到的是英文的示例。

修好了自动填入的值只显示韩文的问题。

写模板时下面那排可以点的值，日期、时间、时区、货币、问候语、城市，一直只用韩文站着。不是翻译得不好，是这几个名字从来没有进过翻译表，所以连英文用户看到的也是韩文。现在四种语言都对了。

顺手把几处漏掉的文字补上了。

繁體中文

中文來了。

有一位朋友問，能不能加上中文的支援。加上了，簡體和繁體兩套。選單列、快速貼上面板、設定，每一個畫面都用中文站著，App 的名字也跟著一起變。

繁體不是只把字換掉。用的是台灣那邊在用的說法，引號也照那邊的寫法，系統設定的路徑寫得和實際畫面對得上。只換字的話，台北的讀者眼前留下的還是別人家的說法。

第一次開啟時給你的示例短語，現在跟著裝置語言走。以前裝置是中文的話，拿到的是英文的示例。

修好了自動填入的值只顯示韓文的問題。

寫範本時下面那排可以點的值，日期、時間、時區、貨幣、問候語、城市，一直只用韓文站著。不是翻譯得不好，是這幾個名字從來沒有進過翻譯表，所以連英文使用者看到的也是韓文。現在四種語言都對了。

順手把幾處漏掉的文字補上了。

배포 메모

- 버전 5.0.5, 빌드 18(`Version.xcconfig`). **새 권한·엔타이틀먼트 없음**
  ⚠️ 17 로 올렸다가 "must contain a higher version than [17]" 로 거절됐다.
  올리기 전에 App Store Connect 의 최신 빌드 번호를 보고 그보다 큰지 확인할 것
- 5.0.4 를 건너뛰었다. 아이폰 앱 5.0.5 와 번호를 맞추기 위해서고, 맥에는 5.0.4 판이 없다.
  App Store Connect 에 5.0.4 를 만들어 둔 것이 있으면 지우거나 5.0.5 로 바꿀 것
- `knownRegions` 에 `zh-Hans`, `zh-Hant` 를 더했고 `ClipKeyboard.tap/zh-Hans.lproj`,
  `zh-Hant.lproj` 의 `InfoPlist.strings` 로 표시 이름이 지역마다 다르게 나간다
  (간체 剪贴键盘, 번체 剪貼鍵盤 — 아이폰 앱과 같은 값)
- `INFOPLIST_KEY_CFBundleDisplayName` 을 `클립키보드` 에서 `ClipKeyboard` 로 바꿨다.
  `.lproj` 가 언어별로 덮으므로 한국어 사용자에게 보이는 이름은 그대로다.
  달라지는 것은 지원하지 않는 언어로 맥을 쓰는 경우인데, 그쪽도 전에 `en.lproj` 로
  떨어졌으므로 화면은 같다. Info.plist 에 구워지는 기본값만 `developmentRegion = en` 과 맞췄다
- `MacSampleSeeder` 의 `isKorean: Bool` 을 `SampleLanguage` 로 바꿨다. 중국어는
  `languageCode` 만으로 간·번체를 못 가르므로 `script` 를 보고, 비어 있으면
  지역(TW/HK/MO)으로 판정한다
- 카탈로그에 `날짜`·`시간`·`타임존`·`통화`·`인사`·`도시` 여섯 키를 새로 넣었다.
  코드는 전부터 `NSLocalizedString` 으로 부르고 있었는데 키가 없어 원문이 그대로 나왔다

⚠️ 아직 안 맞춰 둔 것

- **번체 용어가 아이폰 앱과 갈린다.** 맥은 `剪貼板`·`回復`, 아이폰은 `剪貼簿`·`恢復` 다.
  같은 제품인데 기기마다 다른 단어가 나온다. 한쪽으로 정할 것
- 아이폰 레포의 `scripts/make_zh_hant.py` 가 이 카탈로그도 처리하게 넓히면 위 갈림이
  구조적으로 생기지 않는다. 어휘표에 맥 전용어(`選單列` 등)를 더해야 한다
  (이 문서의 번체 문안은 그 파이프라인으로 뽑고 `選單列` 만 손으로 고쳤다)
- **스토어 현지화가 아직 없다.** 중국·대만 페이지의 이름·부제·설명·키워드·스크린샷은
  코드 밖이다. 이름과 부제 문안은 `docs/APP_STORE_NAMING.md` 에 있다
- 공유 파일 드리프트 2건(`Shared/DefaultsKey.swift`, `Shared/AppSymbol.swift`)이
  남아 있다. `sh scripts/sync_shared.sh`

⚠️ 실기기 확인

1. 시스템 설정에서 맥을 간체로 바꾸고 앱을 켠다. 메뉴바 메뉴, 환경설정, 온보딩이 중국어인지 본다
2. 독과 메뉴바 이름이 剪贴键盘 인지 본다
3. 번체로 바꾸고 환경설정 > 단축키 탭의 빠른 붙여넣기 패널 설명이 번체 표기인지 본다
   (5.0.5(20)에서 접근성 권한 안내 문구는 삭제됐다 — 아래 "2.4.5 대응" 참고)
4. 새 사용자로(또는 `macDefaultSamplesSeeded_v1` 을 지우고) 켜서 예시 단축어가 중국어인지 본다
5. 단축어 추가 화면에서 자동 값 칩이 日期·時間·時區·貨幣·問候語·城市 로 뜨는지 본다

## Guideline 2.4.5 대응 — 5.0.5 (20)

5.0.5(18)이 접근성(손쉬운 사용) API를 접근성 목적이 아닌 용도로 쓴다는 사유로 리젝됐다.
문제는 단 하나, 다른 앱에 ⌘V 키 이벤트를 주입하던 `CGEvent.post(tap: .cghidEventTap)` 였다.

제거한 것
- `DirectPasteHelper.swift` (파일째 삭제) — ⌘V 주입, 권한 확인, 권한 요청 알림
- `GlobalHotkeyManager.checkAccessibilityPermission()` — 전역 단축키에는 접근성 권한이
  필요 없는데도 앱 실행 즉시 권한 팝업을 띄우고 있었다. Carbon `RegisterEventHotKey` 는
  권한 없이 동작한다
- 환경설정의 "Paste behavior" 섹션(자동 붙여넣기 토글, 권한 상태, Grant Access 버튼)
- 컨텍스트 메뉴 "Copy and Paste", 템플릿 시트 "복사 후 붙여넣기", 팝오버 ⌥Return 경로
- 환경설정 단축키 탭의 "전역 단축키에 접근성 권한이 필요합니다" 안내 (사실이 아니었다)

유지되는 것 — 전부 권한 없이 동작한다
- ⌃⇧V 전역 단축키와 플로팅 패널 (`RegisterEventHotKey` + non-activating `NSPanel`)
- 메뉴바 팝오버, 팝오버 밖 클릭 감지(마우스 전용 global monitor — 키보드만 권한이 필요하다)
- 클립보드 복사, 검색, 카테고리, Touch ID 보안 단축어

동작 변화는 하나뿐이다. 단축어를 고르면 클립보드에 복사되고 패널이 닫힌다.
패널이 non-activating 이라 전경 앱이 포커스를 잃은 적이 없으므로 사용자가 그 자리에서
⌘V 를 누르면 된다.

검증
- Release 클린 빌드의 바이너리에 `AXIsProcessTrusted*` / `AXUIElement*` /
  `CGEventPost` / `CGEventCreateKeyboard` 심볼이 하나도 없다 (`nm -u`)
- 번들 리소스의 어떤 언어에도 접근성·권한 안내 문자열이 남아 있지 않다
- Info.plist 에 UsageDescription 키가 없다
